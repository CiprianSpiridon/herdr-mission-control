# GitHub PR adapter grounding

Checked against official documentation on 2026-10-31. These are schema and API references, not proof of an authenticated GitHub request or installed native behavior.

- [REST pull requests](https://docs.github.com/en/rest/pulls/pulls): list with `state=all`, `sort=updated`, `direction=desc`, bounded `per_page`/`page`. Use actual `user`, `head`, `base`, `merged_at` and source URLs; read access is distinct from modifying a PR.
- [GraphQL pull requests](https://docs.github.com/en/graphql/reference/pulls): `headRef` is nullable; retained `headRefName` and `headRefOid` can exist after deletion. Names and SHAs alone do not prove a live ref. `reviewDecision` is nullable. `reviewThreads` is independently paginated; `isResolved` and `isOutdated` support the explicitly bounded actionable-thread aggregate. `statusCheckRollup` describes the head's check/status rollup. Null, denied and partial collections must remain distinguishable from a complete empty collection.
- [Check runs](https://docs.github.com/en/rest/checks/runs): check-run status and conclusion are separate. A completed run can have failure, cancellation, timeout, neutral or skipped conclusions; unknown/missing states must not become success.
- [Commit statuses](https://docs.github.com/en/rest/commits/statuses): the combined state covers status contexts, while the Checks API supplies check runs. No contexts is not proof of passing checks. Respect complete collection evidence before enabling a repair action.
- [GraphQL checks](https://docs.github.com/en/graphql/reference/checks) and [commits](https://docs.github.com/en/graphql/reference/commits): a CheckRun's CheckSuite exposes `commit { oid }`; `headSha` belongs to mutation inputs, rather than that output object. StatusContext and StatusCheckRollup also expose their associated commit. Selected metadata checks these commit IDs against the captured head SHA. Fixture success alone does not validate a live GraphQL query.

The current plan owns the adapter/model contract in `mission-control-github.json`, TASK-044. The shared launcher currently creates a universal `tab.new.task` from `source.key/title/url/body`; optional tool instructions are a separate capability. Tests must inspect that actual first-launch task for each PR action. Its deduplication uses source kind, connection, site and ID plus local host/repo/tool, so PR IDs must encode the remote owner/repo/number.
